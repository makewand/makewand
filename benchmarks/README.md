# 可复验的对照评测

目前没有足够的完整对照数据证明 Makewand 优于单模型。此目录提供固定任务、独立验收和自动化执行器；CI 使用桩验证执行器，不进行模型调用，也不把桩结果作为产品质量数据。

## 已纳入版本控制的内容

- `fixtures/intervals/`：闭区间合并，覆盖排序、边界、非法区间和输入不变性。
- `fixtures/slugs/`：Unicode 规范化和全局唯一 slug，覆盖空值、自然数字后缀与重复冲突。
- 每个案例都有相同的初始源码、完整提示词及在候选工作区外运行的标准库验收脚本。
- `prompts/` 保留历史探索任务；它们不参与本自动验收矩阵，不作为已验证结果。

## 执行

需要 Python 3.9+。默认仅打印计划，不调用模型：

```bash
./benchmarks/run.sh --repeats 3 --seed 20260927
python3 -I benchmarks/test_runner.py
```

复制 `arms.example.json` 到一个自定义文件，为单模型基线加入已在本机验证的命令 argv 列表。每个参数支持 `{prompt}`、`{prompt_file}`、`{workspace}`、`{timeout}`；不经 shell 展开。供应商 CLI 参数因版本而异，执行前记录各 CLI/模型版本，并确保命令退出前已经把源码写入工作区。示例中的三个 Makewand 档位不是单模型基线。

显式执行会消耗当前工具的订阅额度或已启用 API 模式的费用：

```bash
./benchmarks/run.sh --arms /path/to/arms.json --timeout 600 --repeats 3 \
  --seed 20260927 --output /tmp/makewand-benchmark-results --execute
```

所有 arm 使用相同提示词、初始源码、墙钟预算和验收脚本，按固定种子随机排序。超时会终止进程组。输出目录必须不存在，避免覆盖旧证据。候选与验收均可执行代码，应只在用于评测的隔离环境中运行；本执行器不是恶意代码安全边界。

## 结果与解释

`plan.json` 保留命令模板、随机顺序、预算和 fixture 内容摘要。每次运行保存生成/验收的退出码、时延、stdout/stderr、产物摘要和文件模式。生成命令成功但独立验收失败，或验收过程中修改产物，均不计为通过。`summary.json` 汇总验收数、基础设施失败和 P50/P95 生成时延。

供应商调用次数、Token 与金额默认为 `null`，不能将未测量的成本写成零。当前统一的是墙钟预算；如需固定调用或 Token 预算，必须在各 arm 的适配器中分别实施并记录。订阅额度、本机资源和人工修订时间也应计入正式实验。

这两个小型确定性任务只能验证狭窄的代码行为，无法支持 UI、安全或大型工程优势主张。正式结论还需要更多预先固定的任务、重复实验、完整单模型对照、模型版本及费用/额度数据。
